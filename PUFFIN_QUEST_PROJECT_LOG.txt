1. WHAT PUFFIN QUEST IS
====================================================================
Puffin Quest is a web app (works in any phone or computer browser,
no install needed) that turns small everyday good habits into a
game. Users ("puffineers") complete little real-life "quests" —
drink water, take a walk, be kind to someone, go find a landmark in
their city — and earn a virtual currency called "Puffins." Some
quests are instantly rewarded; others are shown to other real users
in a swipeable feed so people can cheer each other on.

The whole thing is themed around a cartoon puffin bird mascot, with
a soft, rounded "liquid glass" visual style (translucent frosted-glass
cards, pastel mint/coral/gold colors).

2. HOW THIS PROJECT EVOLVED (CHRONOLOGICAL LOG)
====================================================================

PHASE 0 — Starting point
------------------------
The project began as an existing single-file prototype (one HTML
file) that ran entirely in the browser with no server or accounts.
All progress was stored only on one device, in that browser's local
storage. Nothing was shared between users.

PHASE 1 — Small gameplay tweaks to the prototype
-------------------------------------------------
- Changed the rule for quest photos/captions: both became OPTIONAL,
  each adding a small bonus reward (+2 Puffins for a photo, +1 for a
  caption) instead of a photo being required.
- Added the ability to change your profile picture and profile cover
  photo from the "Bird" (profile) tab, with an edit (pencil) button.

PHASE 2 — Turning it into a real, hosted website
--------------------------------------------------
This was the big rebuild. The user asked for "a real website... that
I can use online," with real accounts and hosting via GitHub/a free
server, using their own domain.

What was built:
- A real backend server (the "brain" of the app that runs on a
  computer in the cloud, not in the visitor's browser) using
  Node.js and a web framework called Express.
- A real database (PostgreSQL) that permanently stores every user's
  account, progress, photos, and history — so your progress is the
  same no matter what device or browser you use.
- Real user accounts: register with a username and password
  (passwords are scrambled/"hashed" before storage, so even the
  app's own database never holds a readable password).
- A genuine multi-person "Review Cove": instead of the old prototype
  faking 3 anonymous reviewers, real registered users could swipe
  through other people's submitted quest photos and approve or skip
  them. Two permanent "bot" accounts were added so a submission is
  never stuck waiting forever even if no other real person is
  online — 2 bot approvals plus 1 real approval was the original
  rule (this was changed again later — see Phase 5).
- The code was pushed to a GitHub repository (a cloud-hosted, version-
  controlled copy of the code) so it has a permanent history and can
  redeploy automatically.
- Deployed to Render.com, a free hosting service. Render was set up
  to automatically rebuild and redeploy the live site every time new
  code is pushed to GitHub.
- Connected the user's own domain (greenuplabs.com, managed at
  Hostinger) so the site is reachable at
  https://puffinquest.greenuplabs.com with a proper HTTPS padlock
  (secure connection), not just the default Render web address.
- Along the way, fixed a deployment mix-up (the very first Render
  setup had a typo in its start command and the wrong project folder
  selected) by redoing the setup using Render's "Blueprint" feature,
  which reads a configuration file from the code repository and sets
  everything up automatically and correctly.
- Fixed a DNS conflict: the custom domain briefly failed to work
  because Hostinger's own website hosting feature was still
  "claiming" that web address behind the scenes, blocking the
  correct DNS record from taking effect. Removing that unused
  Hostinger website slot fixed it.

PHASE 3 — Social features and account safety
-----------------------------------------------
- Usernames were made unique (no two accounts can share one).
- Added optional social account linking: during sign-up (or later,
  from the profile edit panel), a user can tick Facebook, Instagram,
  and/or LinkedIn. The app automatically builds the correct profile
  link for each (e.g. facebook.com/yourusername) — no need to paste
  a URL by hand.
- Those linked accounts show up as small clickable logo icons (using
  the real, brand-colored Facebook/Instagram/LinkedIn logos) on a
  user's profile and on their photo cards in the review feed, so
  other people can visit their real social profiles.
- Along the way, a testing mishap was investigated and disclosed:
  while testing photo uploads, a stray photo of a real person's face
  appeared in a local test database. This was immediately
  investigated, the file was deleted, and all test data was wiped.
  The most likely explanation is that the online testing tool used
  to click through the app automatically filled in a placeholder
  image when a "take a photo" button was clicked, rather than any
  real camera being accessed. This never affected the live website —
  it happened only in a temporary local copy of the database used
  for testing on the developer's own machine.

PHASE 8 — Connection & Account Creation Stability Fixes
-------------------------------------------------------
Resolved issues where users could not connect or create accounts:
- HTTP 304 Caching: Express web server was generating ETags on API
  responses, causing browsers to receive empty 304 Not Modified responses
  when fetching fresh user data. Fixed by disabling ETags (app.set("etag", false)),
  enforcing Cache-Control: no-store across all API routes, and requesting
  cache: "no-store" in client fetches.
- PostgreSQL Array Column Parsing: Array columns (titles, badges,
  daily_done_ids, fun_done_ids) returned as raw strings (e.g. "{}") in
  pg-mem and certain pg driver setups, crashing frontend array calls
  (.forEach). Fixed by configuring an OID 1009 array parser in db.js and
  adding universal toArray() sanitization across gamestate, quests, and
  city route handlers.
- Correlated Review Subqueries: Decoupled subqueries in the Cove review
  flow to ensure fast, reliable queries across both local development
  and production Render/Neon PostgreSQL.

PHASE 9 — City Challenge Auto-Approval & 3-Puffin Verification Patrol (in Fight part)
-------------------------------------------------------------------------------------
Per user instructions, the City Challenge (located inside the "Fight" tab)
was upgraded with automated AI verification and location proximity matching:
- Located in the Fight Part: The City Challenge lives in the "Fight" tab
  (⚔️ Fight), where players choose their city (Hanoi, Ho Chi Minh City,
  or Singapore) to discover mystery landmarks behind blurred zoom clues.
- Two Strict Criteria for Instant Auto-Approval:
  1. Criterion 1 (AI Picture Fit): Uploaded photo is analyzed by an AI
     vision detection engine against the landmark's architectural profile
     (structural features, color distribution, visual entropy). It must
     fit ~80–90% (threshold >= 80%) to pass.
  2. Criterion 2 (Location Match within +-10 meters): The player's GPS
     location is verified against real-world landmark coordinates using the
     Haversine formula. Strictly enforces a maximum distance tolerance of
     +-10 meters.
  - If both criteria match, the challenge is AUTO-APPROVED immediately
    within the system — no Cove community review or human check is needed!
- Animated 3-Puffin Verification Loading Sequence:
  After submitting, exactly 3 animated puffins appear in a sequential
  loading patrol:
  - Puffin 1 (GPS Scout 🐧🧭): Checks if location is within +-10m. If
    matched, marks "✓ Within +-10m". If not, notes the distance (e.g.
    "⚠️ 556m away") and STILL proceeds to Puffin 2 so the user gets full
    feedback on their photo.
  - Puffin 2 (AI Detective 🐧🔍): Runs AI detection and reports visual
    similarity (e.g. "✓ ~94% Match" or "✕ Under 80%").
  - Puffin 3 (Chief Puffin 🐧🌟): Issues the final verdict:
    - Auto-Approved: Awards Puffins (+40 to +43), bursts confetti, updates
      balance, advances user streak, and unlocks the next landmark.
    - Rejected: Details exactly what needs adjustment (GPS, photo, or both)
      and provides a "🔄 Try Again / Retake Photo" button so the challenge
      can be redone immediately until finished.
- Testing Convenience Aid: Added a "📍 Test at Landmark (±0m)" button in
  the modal so testers and players can simulate exact landmark coordinates
  without having to travel to Vietnam or Singapore.

- Clear User Feedback:
  - Header, placeholder, and action buttons explicitly display the rewards:

  - Dynamic toast notifications detail: "+2 Puffins (includes +1 feedback bonus!)" or "+1 Puffin reward".

3. FEATURES IN DETAIL (WHAT THE APP CAN DO TODAY)
====================================================================

3.1 Accounts
------------
- Sign up with a username (3–20 characters) and a password (at least
  6 characters).
- Usernames are guaranteed unique.
- Passwords are never stored in plain, readable form.
- A logged-in session lasts up to 180 days before needing to sign in
  again.
- There is currently no "forgot password" self-service reset — this
  is a known gap for later.

3.2 Today's Quest
-----------------
- Everyday healthy and kind habits (drinking water, a short walk,
  eating veggies, 10 minutes of exercise, tidying up, etc.) that users
  can finish each day.
- Rewarded INSTANTLY — no one needs to check or review them.
- Reward is +1 to +5 Puffins (+optional bonuses: +2 for photo, +1 for
  caption, +1 for GPS).
- Once a Today's Quest is completed, it drops out of the active grid.
- A shuffle/reroll button lets the user swap today's quests for a fresh
  random 3 at any time.
- Resets automatically every day.

3.3 Cove Quest (formerly Cool & Fun Quests)
-------------------------------------------
- One-off adventures, worth extra Puffins when approved by community
  (16–35 base Puffins).
- Users upload proof to verify completion: to go to the community, you must take
  a picture (mandatory photo or video thumbnail). GPS is optional and grants a
  +1 bonus Puffin.
- Explicit note on GPS: "📸 To go to the community, you must take a picture · 📍 Share GPS (optional)".
- The GPS button is explicitly named "📍 Share GPS (optional)".
- Submissions are moved to the community Cove for other puffineers to
  review, approve, or reject.
- In the submission modal, an "Automatically post to your bird profile"
  toggle checkbox is checked by default, but users can unclick it if
  they prefer to keep the quest unlisted on their public profile (persisted via localStorage).
- After completing or submitting, a shareable link can be sent to a
  friend to cheer or review directly.

3.4 Community Cove (the review deck)
------------------------------------
- The community review feed where puffineers inspect fellow players'
  Cove Quest proof submissions.
- Swipe right (or tap "✓ Approve (+1 🪙)") to approve authentic proof; swipe
  left (or tap "✕ Reject (+1 🪙)") to reject.
- Reviewer Rewards:
  * Base Reward: Reviewing any submission grants +1 Puffin, regardless of whether
    the player decides to Approve or Reject ("no wonder the reject or approve").
  * Feedback or Encouragement Bonus: If the reviewer enters feedback or words of
    encouragement, they receive an additional +1 Puffin (+2 Puffins total).
- Approving authentic proof advances the submission towards community finalization
  (2 approvals needed) and grants the creator their full Puffin bounty upon finalization.
- Supports tactile stamps, feedback comments, and smooth glass animations.

3.5 Fight Tab (3-Option Carousel)
----------------------------------
- Segmented Liquid Glass 3-way navigation:
  1. "⏱️ Timely Challenge": Three ongoing bonus challenges running in parallel:
     - Weekly (Waddle Sprint): complete 5 quests this week. Awards Puffin bounty +
       🌟 Waddle Star badge + 🪶 Swift Waddler title.
     - Monthly (Puffin Tide): earn 150 Puffins this month. Awards Puffin bounty +
       🌊 Tide Champion badge + 🪶 Puffin Monarch title.
     - Seasonal (Golden Feather Rally): reach a 14-day daily streak this season.
       Awards Puffin bounty + 🪶 Golden Plume badge + 🪶 Century Waddler title.
     Each can be "claimed" once its target is reached, and automatically resets at
     the start of its next period.
  2. "🏙️ City Challenge": Mystery landmark discovery with AI vision matching and
     +-10m GPS tolerance (detailed in 3.6). Explicitly excluded from Bird profile.
  3. "⚔️ Fight Puffins": Real-time PvP duel matchmaking. Players can create custom
     duel challenges, wager stakes (10, 25, 50, 100 Puffins), invite specific friends
     or queue for random matchmaking. Opponents can accept or reject invitations. Both
     players race on a shared quest; first to finish wins the full wager pot!

3.6 City Challenge (in the Fight part)
---------------------------------------
- Located in the "Fight" tab (⚔️ Fight).
- A user picks one of three real cities: Hanoi, Ho Chi Minh City, or
  Singapore.
- Shows one mystery landmark at a time with a blurred, zoomed clue and a
  riddle-like hint.
- Automatically approved within the system when matching 2 strict criteria:
  1. AI Picture Fit: Uploaded photo is analyzed with AI to ensure it
     fits the original landmark picture (~80–90% fit, threshold >= 80%).
  2. Location Proximity Match: The player's GPS coordinates must match the
     landmark location within +-10 meters tolerance.
  - When both criteria pass: AUTO-APPROVED immediately without needing
    Cove community review or human check!
- Animated 3-Puffin Verification Patrol:
  Upon submission, 3 animated puffins inspect the entry in sequence:
  - Puffin 1 (GPS Scout): Verifies location proximity (within +-10m).
    If not matched, notes the distance and moves to Puffin 2.
  - Puffin 2 (AI Detective): Scans photo and evaluates visual fit (~80-90%).
  - Puffin 3 (Chief Puffin): Final verdict — awards +40 to +43 Puffins and
    celebrates with confetti if approved; if rejected, provides detailed
    feedback and a "Try Again" button so the player can redo the challenge
    immediately until finished.
- Testing Aid: Includes a "📍 Test at Landmark (±0m)" button in the modal
  to simulate exact landmark coordinates during testing.
- Profile Journal Exclusion: City Challenges are exclusively challenges and
  never appear on the user's Bird profile journal.

3.7 Fish Tab: Central Puffin Mascot, Growth & Wardrobe Dress-Up

4. HOW IT'S BUILT (PLAIN-ENGLISH TECHNICAL SUMMARY)
====================================================================
- One server program (written in JavaScript, using Node.js and the
  Express framework) handles everything: it serves the visual app to
  your browser AND answers all the behind-the-scenes data requests
  (logging in, submitting a quest, fetching your profile, etc.).
- One database (PostgreSQL) is the single permanent record of every
  user, every submitted quest, every review/cheer, and every fishing
  catch. Photos are stored as small, compressed thumbnail images
  directly inside the database (not a separate photo-hosting service).
- The visual app itself (what you see and click) is built with plain
  web technology (HTML, CSS, and JavaScript) with no special app
  framework and no separate "build" step — it's straightforward and
  easy to maintain.
- The whole thing is hosted on Render.com's free tier: one small
  always-available web server plus one small database, at no cost.
- The source code lives on GitHub. Every time new code is saved there,
  Render automatically rebuilds and republishes the live site within
  a couple of minutes.
- The custom domain (puffinquest.greenuplabs.com) is pointed at the
  Render server through a DNS setting managed at Hostinger, with a
  secure HTTPS certificate issued automatically.

6. A real, more serious bug: the database stores "what day it is" as
   a special date format, but the code was comparing that against a
   plain text date using a check that could never succeed — meaning,
   in effect, every visit was silently treated as "a new day," which
   reset each user's daily-quest completion tracking almost
   constantly. This has been fixed at the source so daily progress is
   now correctly remembered.
7. HTTP 304 Caching on API requests: The Express server generated ETags
   by default, causing browsers to receive empty 304 Not Modified responses
   for API calls when cached, which broke live data updates and login.
   Fixed by disabling server ETags (app.set("etag", false)), adding
   Cache-Control: no-store across all API routes, and enforcing
   cache: "no-store" in frontend fetch requests.
8. PostgreSQL array column parsing: Columns stored as PostgreSQL text
   arrays (titles, badges, daily_done_ids, fun_done_ids) returned as raw
   strings (e.g. "{}") in pg-mem and certain pg driver configurations,
   crashing client array operations (.forEach is not a function). Fixed by
   registering an OID 1009 array parser in db.js and wrapping all array
   reads in a universal toArray() sanitizer across backend routes.
9. Correlated review subqueries: Subqueries referencing outer table aliases
   failed in in-memory previews during local development. Decoupled review
   queries cleanly in cove.js and gamestate.js for maximum performance and
   reliability.

7. KNOWN LIMITATIONS / THINGS TO KEEP IN MIND
====================================================================
- No self-service "forgot password" flow yet.
- Render's free hosting plan "falls asleep" after about 15 minutes of
  no visitors; the next visitor after that may wait up to about a
  minute for the site to wake back up.
- Render's free database is automatically deleted 90 days after it
  was created unless it is upgraded to a paid plan or its data is
  backed up/migrated beforehand. IN PROGRESS: the decision is to move
  the database to Neon, a different provider whose free PostgreSQL is
  permanent rather than time-limited. The code is ready for the move
  and the step-by-step runbook is in
  docs/DATABASE_BACKUP_AND_MIGRATION.md. The remaining work is manual
  account setup that only the owner can do: create the Neon project,
  run the backup, load it into Neon, and paste the new connection
  string into Render. Hostinger cannot host this database — its
  shared/Premium plans offer MySQL only, not PostgreSQL. It can hold
  the backup FILES, and it keeps handling the domain either way.
- Live updates (e.g., seeing a cheer from someone else appear) rely
  on the app periodically checking for changes every few seconds,
  rather than appearing instantly.
- Photos are stored as small compressed thumbnails inside the
  database rather than a dedicated photo-hosting service, which is
  simple and free but keeps photo quality modest.
- Real AI Vision Key: Configured with Google Gemini Multimodal Vision
  API using the active model (gemini-3.6-flash with automated fallback),
  enabling live AI photo review (~80-90% match threshold) paired with
  mandatory GPS proximity (within +-10m) for City Challenges.
